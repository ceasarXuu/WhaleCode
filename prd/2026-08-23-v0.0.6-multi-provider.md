## 1. Background And Product Intent

Whale 当前以 DeepSeek 为默认 Provider，并保留 Codex 原生 OpenAI 认证与 Provider 基础设施。用户需要在同一个 TUI 中显式选择 OpenAI 订阅、OpenAI API 或 DeepSeek，而不是手工改环境变量、配置文件并重启。

Provider 切换不只是 endpoint 变化。它会改变认证、可选模型、系统提示词、工具与命令能力、上下文窗口、压缩方式、历史 wire 兼容性、费用归属和恢复语义。本功能要让这些变化成为一致、可理解、可恢复的产品行为。

## 2. Goals And Success Criteria

- 用户可通过 `/provider` 查看当前选择并切换到首批三种访问方式。
- OpenAI 订阅与 OpenAI API 使用 Codex 已有登录、存储和刷新能力。
- DeepSeek 缺少凭据时可安全输入 API Key，且 Key 不出现在对话、日志、rollout 或错误中。
- 切换完成后，模型目录、默认模型、提示词、工具、命令、上下文限制与压缩策略保持同一 Provider 快照。
- 同一 session 的后续 turn 能在保留有用上下文的同时，避免向目标 Provider 发送不兼容历史。
- 切换、恢复、fork、rollback 与成本审计能够还原每段对话使用的 Provider。
- 任一切换预检失败时，用户仍可继续使用切换前的 Provider，不产生半切换状态。

## 3. Users And Usage Context

面向在 Whale TUI 中进行长对话 coding 工作的开发者，包括：

- 使用 ChatGPT/Codex 订阅的用户；
- 使用 OpenAI API 计费的用户；
- 使用 DeepSeek API 的用户；
- 在同一任务中因能力、成本或可用性需要切换模型服务的用户。

## 4. Scope

### In Scope

- TUI `/provider` 入口、当前状态和三种首批选择。
- OpenAI 原生订阅/API 认证复用与访问方式切换。
- DeepSeek API Key 录入、使用、更新和错误处理。
- Provider-scoped 模型目录、默认模型和缓存。
- `/model` 的跨 Provider 统一目录与直接切换。
- Provider 切换后的系统提示词、工具、命令和压缩策略更新。
- 同一 session 中 turn 边界的上下文兼容处理。
- Provider transition 的持久化、resume/fork/rollback/subagent 语义与审计。
- 无敏感信息的状态、错误和诊断输出。

### Out Of Scope

- 首批三种选择以外的新 Provider。
- Provider 聚合代理、负载均衡、自动故障转移或按请求自动路由。
- 同一 turn/tool loop 中把不同请求分发给不同 Provider。
- 质量或价格自动推荐；除非后续由用户明确加入范围。

## 5. Core User Journey

1. 用户输入 `/provider`。
2. Whale 显示当前 Provider、访问方式、当前模型和可用选择；用户也可从 `/model` 的统一目录直接选择任一 Provider 的模型。
3. 用户选择 OpenAI 订阅、OpenAI API 或 DeepSeek。
4. 若缺少所需凭据，Whale 启动对应登录或 Key 录入流程；用户可取消并回到原状态。
5. Whale 校验目标访问配置及其默认/已选模型，评估当前 session 历史兼容性。
6. Whale 原子提交待生效切换，并明确显示目标 Provider、访问方式、模型和生效时机；下一 turn 使用新的能力面。
7. 若切换失败，Whale说明可恢复错误，继续保留原 Provider。

## 6. Interaction And Information Design

`/provider` 至少需要展示：

- 用户可理解的选择名称；
- 当前选中状态；
- 认证状态，不显示任何 Key/token；
- 目标默认或当前模型；
- 需要登录、需要输入 Key、不可用或切换待生效等状态；
- 取消、重试、更新凭据和切换成功/失败反馈。

OpenAI 订阅与 OpenAI API 在用户界面中是两个明确选项，但底层可共享 `openai` Provider。内部结构不得迫使用户理解 wire Provider 与 auth mode 的区别。

`/model` 展示当前应当可见的 Provider 模型，不要求用户先执行 `/provider`。列表按用户可见的 Provider/访问方式分组：`OpenAI 订阅`、`OpenAI API`、`DeepSeek`。OpenAI API 尚未配置时，整个 `OpenAI API` 分组及其模型候选不得出现；配置成功后才展示。OpenAI 订阅可用时必须显示独立的 `OpenAI Subscription` 分组标题并紧邻其模型候选。同名 OpenAI 模型可分别出现在两个已配置的 OpenAI 组中，用户选择的分组直接确定访问方式。选择其他可见组的模型等价于同时选择其 Provider、访问方式与模型。

## 7. Product Rules And State Logic

- Provider 或跨 Provider 模型选择必须同时确定访问方式与一个对目标 Provider 有效的模型。
- 目标访问方式优先恢复它在当前 session 中上次成功使用的模型；没有记录时使用其默认模型。
- Provider 不兼容的命令仍在命令列表中以不可用状态呈现，并给出不支持原因；直接输入时不得执行，必须返回同一原因。工具能力不得错误暴露给模型。
- 切换状态必须可重放；当前 session 的 thread state 与后续新 session 的默认配置必须各自成功更新。
- 模型选择同时确定 Provider、访问方式、模型与 reasoning effort；成功选择后更新当前 session，并将同一完整选择保存为后续新 session 的默认值。
- 默认选择不得只保存模型名，也不得在 OpenAI 订阅与 OpenAI API 凭据并存时靠猜测恢复访问方式。
- active turn 期间允许完成 UI 选择并显示“下一 turn 生效”；当前 turn 的模型、工具循环和 Provider 快照保持不变。
- DeepSeek Key 默认按 Provider 安全持久化并复用；不得写入 OpenAI 凭据字段。
- OpenAI 订阅 token 与 OpenAI API key 使用相互隔离的安全凭据槽并可一键互切；登录或登出其中一种访问方式不得覆盖或清除另一种。
- 跨 Provider 历史保留 canonical 事实，只为目标 Provider 生成兼容的 wire projection；仅在窗口或压缩策略要求时压缩，不因切换无条件摘要或新建 thread。
- `/logout` 只清除当前访问方式的凭据，不连带清除其他 Provider/访问方式。
- 用户取消或任何预检失败，不得改变当前有效 Provider。
- 凭据不得进入模型上下文、rollout、telemetry、普通日志或可复制错误文本。
- session 中途切换遵循 turn 边界，切换排队状态、成功、失败和恢复均需可理解且可重放。

## 8. Edge Cases, Errors, And Recovery

- 目标凭据缺失、为空、错误、过期或网络验证超时。
- 目标 Provider 没有可用模型，或当前模型不属于目标 Provider。
- 切换时存在 active response、工具调用、重试、compact 或排队输入。
- 旧历史含目标 Provider 不支持的 reasoning、hosted tool、图片、namespace tool 或 compact checkpoint。
- 目标模型 context window 小于当前历史。
- 切换后立即退出、崩溃、resume、fork、rollback 或创建 subagent。
- 登录或 Key 更新成功，但 Provider transition 失败。
- 从 OpenAI 订阅切到 OpenAI API 时 endpoint/auth 变化但 Provider ID 不变。
- `/model` 中同名 OpenAI 模型按访问方式分别归组，所选分组即为确定路由，不依赖隐式猜测。

## 9. Content And Terminology

- 用户可见名称：`OpenAI 订阅`、`OpenAI API`、`DeepSeek`。
- `Provider` 表示模型服务选择；界面不要求用户理解内部 Provider ID。
- `访问方式`用于区分 OpenAI 订阅与 OpenAI API。
- 错误文案只说明凭据类型、状态和恢复动作，不显示任何凭据片段。

## 10. Acceptance Criteria

- Given 任意 session，when 用户输入 `/provider`，then 能看到当前选择及三种首批选项；active turn 中选择时明确显示下一 turn 生效且不改变当前 turn。
- Given 未登录 OpenAI 订阅，when 用户选择 OpenAI 订阅，then 启动 Codex 原生登录且可取消回到原 Provider。
- Given 未配置 OpenAI API，when 用户选择 OpenAI API，then 复用 Codex 原生 API Key 登录且不会泄露 Key。
- Given 未配置 DeepSeek，when 用户选择 DeepSeek，then 提供明确 Key 输入流程，Key 不进入历史、日志或 telemetry。
- Given 目标访问配置有效，when 切换成功，then 后续 turn 的 Provider、模型、提示词、工具、命令和压缩策略来自同一目标快照。
- Given 当前模型不属于目标 Provider，when 切换，then 优先使用当前 session 记录的目标访问方式上次成功模型，否则使用目标默认模型。
- Given OpenAI API 尚未配置，when 用户打开 `/model`，then 不显示 `OpenAI API` 分组或其任何模型候选，但 `/provider` 仍显示 OpenAI API 配置入口。
- Given OpenAI API 已配置，when 用户打开 `/model`，then 显示独立的 `OpenAI API` 分组及其模型候选。
- Given OpenAI 订阅可用，when 用户打开 `/model`，then 显示独立的 `OpenAI Subscription` 分组标题，且标题位于其模型候选之前。
- Given 用户输入 `/model`，when 模型列表打开，then 当前可展示的 Provider 模型按访问方式分组，用户可直接选择其他可见组的模型而无需先执行 `/provider`。
- Given 同一 OpenAI 模型同时支持订阅与 API，when 用户从其中一个分组选择，then 该分组明确决定使用对应凭据和计费路径。
- Given OpenAI 两种访问方式都已登录，when 用户在它们之间切换或登出其中一种，then 另一种凭据继续安全保留且仍可使用。
- Given 某命令不受当前 Provider 支持，when 用户查看命令列表或直接输入该命令，then 看到不可用状态和明确原因，且命令不执行。
- Given 历史包含不兼容 item，when 后续请求发往新 Provider，then canonical 历史保留且 wire projection 不发送不兼容形状。
- Given 任一预检或提交失败，when 用户继续对话，then 原 Provider 仍完整可用。
- Given 切换后重启并 resume，when 继续对话，then 恢复最后一次成功提交的 Provider、访问方式和模型。
- Given 用户成功选择任一模型，when 创建后续新 session，then 默认使用最后选择的 Provider、访问方式、模型与 reasoning effort，无需再次选择。
- Given OpenAI 订阅与 OpenAI API 凭据并存，when 用户选择其中一组模型后创建新 session，then 精确恢复所选访问方式，不得仅凭当前认证缓存猜测。
- Given rollout 与诊断工具，when 查看跨 Provider session，then 能按 turn 还原 Provider 且不含敏感凭据。

## 12. Open Questions And Risks

### Blocking Product Questions

- 无。后续工程设计如发现新的用户可见重大选择，必须重新进入产品确认，不得自行扩展本 PRD 权威。

### Evidence-backed Engineering Risks

- DeepSeek Key 现有文案与存储/读取实现错位，若直接复用会造成“显示已保存但运行时缺 Key”。
- Provider 当前不是可变 thread authority；局部 UI 修改会产生 UI、core 和持久化状态分裂。
- 模型列表当前只保留 DeepSeek，模型缓存又未按 Provider 隔离。
- base instructions 是 session 级固定值；现有 model-switch fragment 不等价于 Provider prompt transition。
- previous-turn/rollout 缺少 per-turn Provider，跨 Provider 压缩、恢复、成本和错误归属不可审计。
- OpenAI 专属 encrypted reasoning 与 hosted items 尚无到 DeepSeek 的完整 wire sanitizer。
