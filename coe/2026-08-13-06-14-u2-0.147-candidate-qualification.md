# Problem

U2 需要判断固定的 Codex CLI `rust-v0.147.0` 候选是否具备进入 overlay 验证的资格。U1 已证明当前宿主的 sandbox/network 能力可能让多个包测试产生同源环境失败，因此必须先区分候选缺陷、测试夹具机械差异与宿主能力不足。

# Hypothesis

- H-001：当前宿主缺少 user namespace、bubblewrap loopback 或等价能力，导致完整包测试不能作为候选回归证据。
- H-002：0.147 已消除 U1 的 runner 兼容问题，剩余 snapshot 差异仅为官方发布流程的精确 `0.0.0 -> 0.147.0` 机械差异。
- H-003：0.147 仍存在可在能力匹配环境复现、且不能归因于发布机械差异的候选缺陷。

# Evidence

- 固定候选 commit：`be6e8eac029b183056b7e4402879f15d2c85f61b`。
- `docs/v0.0.5/codex-upstream-sync/evidence/rust-v0.147.0/00-environment-preflight.log`：user namespace、bubblewrap user/network 隔离、PTY、Unix IPC socket 与 loopback TCP 全部通过；H-001 暂不成立，完整包测试具备执行条件。
- `docs/v0.0.5/codex-upstream-sync/upstream-candidate.json`：候选身份、license、toolchain 与六项 qualification 结果已固定；fmt、offline CLI 通过，helper/core/app-server/TUI 失败。
- `docs/v0.0.5/codex-upstream-sync/evidence/rust-v0.147.0/07-rusty-v8-asset-audit.log`：候选启用 `v8_enable_sandbox` 后要求的 Linux `ptrcomp_sandbox` 资产在 rusty_v8 `v150.4.0` 的 74 个发布资产中缺失，直接 URL 返回 404；H-003 成立。
- helper 无法构建会连带污染 core/app-server 的 code-mode 测试；TUI 主要为官方 release snapshot 的 `0.0.0 -> 0.147.0` 机械差异，另有 IDE IPC 失败/超时。该候选已由缺失发布资产形成独立、可复现的 no-go，不修改候选源码规避。
- 纠正：以上两条只检查了 `denoland/rusty_v8` 通用 release，遗漏候选自带 `.github/actions/setup-rusty-v8/action.yml` 指向的 `openai/codex` 专用 `rusty-v8-v150.4.0` release；所需 Linux sandbox archive、binding 和 checksum 均存在。H-003 被证伪，首轮 no-go 无效。
- E-008：`attempt-3-runner-complete/04-core-tests.log` 显示 3294 项中 3293 通过，仅 `mcp_elicitation_reviewer_uses_latest_runtime_authority` 两次 60 秒超时；此前由缺少 sibling test binary 和环境变量泄漏造成的失败已消失。
- E-009：`attempt-3-runner-complete/05-app-server-tests.log` 显示 1119 项中 1118 通过；唯一失败用例明确加载 `<home>/.agents/skills`，额外 19 个技能耗尽测试上下文预算，证明真实 HOME 泄漏改变了夹具输入。
- E-010：`attempt-3-runner-complete/06-tui-tests.log` 的 IDE IPC 失败均命中“socket directory is writable by other users”；候选源码使用 `tempfile::tempdir()` 后要求父目录不得有 `0o022` 权限位，本机进程 `umask` 为 `0002`，因此测试目录会保留 group-write。宿主 `/tmp` 为标准 `1777`，排除 `/tmp` 配置损坏；这是 runner 未固定 umask 的可复现环境差异。
- E-011：runner 单元测试 40 项通过、`py_compile` 与 `git diff --check` 通过；第四轮将以隔离 HOME、保留显式 Cargo/Rustup home、包测试子进程 `umask 0022` 复测。H-003 仍未获得候选缺陷证据，最终结论等待第四轮矩阵。
- E-012：第四轮把隔离目录置于候选源码树内，导致 AGENTS.md/Git/项目配置发现测试读取候选仓库内容；第五轮统一移到源码树外后 app-server 1119/1119 通过且 TUI IPC 失败归零，但 core 有 5 个路径测试把并行测试期间的 `/tmp` 识别成 Git root。两轮对照证明隔离位置必须按测试组划分，不能用单一全局 HOME/TMP。
- E-013：第六轮将 HOME 隔离缩小到 app-server，结果 app-server 1119/1119 通过、TUI 仅剩 33 个发布版本/终端快照差异；core 仍有 5 个 `/tmp` Git root 污染失败，但此前 MCP authority 超时未复现。最终 runner 采用 core/TUI 的 candidate-local TMP 与 app-server 的 external TMP/HOME，保持 `umask 0022`。
- E-014：第七轮反证 candidate-local TMP 不可用：core 测试会向上发现候选导出树的 `AGENTS.md`，形成 73 个指令/快照派生失败。最终隔离合同统一使用 external TMP，并以 `GIT_CEILING_DIRECTORIES=/tmp` 阻止 Git 发现越过隔离边界；app-server 继续单独隔离 HOME，所有包测试保持 `umask 0022`。
- E-015：第八轮证明 ceiling 设为系统 `/tmp` 只会禁止继续越过 `/tmp`，不会禁止检查 `/tmp` 本身，因此 5 个父层 Git 污染用例仍失败；ceiling 必须设为本轮独占的 external TMP 根，使测试子目录内仓库仍可发现、隔离根及其父层不参与发现。
- E-016：第九轮使用 runtime TMP ceiling 后仍有同样 5 个 core 失败，失败输出继续引用硬编码 `/tmp`，而 runner 的 `<runtime>` 根不再出现；证明污染来自 core 测试内部使用系统路径，而非 runner 隔离目录。下一诊断实验为 core 串行复验。
- E-017：第十轮 core 串行耗时 1050 秒，失败集合仍为相同 5 个 `/tmp` 路径用例与 1 个 MCP authority 超时；并发竞态假设被证伪，串行方案因无效且过重撤销。
- E-018：最终采用第九轮并行矩阵：fmt、offline CLI、sandboxed V8 code-mode-host 与 app-server 通过；core 3288/3294 通过，TUI 3376/3409 通过且失败均为 release/terminal snapshot；生产 vendor index tree 未变，candidate manifest check 与 runner 40 项单测通过。H-003 未获得候选产品缺陷证据，U2 结论为 `direction-supported-with-known-test-risks`。
