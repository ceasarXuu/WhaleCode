# Problem P-001: R5 TaskSpace map may collapse multi-stage work into too few nodes
- Status: repair-partially-validated-followup-in-progress
- Created: 2026-07-10 06:00
- Updated: 2026-07-10 08:48
- Objective: 判断 R5 简化后 Agent 是否把本应由多个目标/依赖节点表达的复杂工作压入极少节点，并区分 sample 过简单、Agent 选择、projection 丢失和 runtime/tool contract 问题。
- Symptoms:
  - `count-call-stack` 只创建一个 `inspect_code_context` node，却在其中完成读取、编辑、测试和验证。
  - node 完成后 map 仍显示 task active、result unreviewed，graph health 报 `high_unreviewed_result_ratio`。
- Expected behavior:
  - 简单任务允许单节点；具有多个独立目标、阶段依赖或产物的复杂任务应由 Agent 在 map 中建立可解释节点/边，而 runtime 不替 Agent 语义拆分。
- Actual behavior:
  - L3 `subscription-billing-repair` 的 Agent 明确生成并维护了 6 阶段 plan，但 TaskSpace map 始终只有一个机械初始化的 `inspect_code_context` node；36 个普通工具结果覆盖读取、环境诊断、四文件编辑、测试和最终复核。
- Impact:
  - 若复杂任务持续单节点，TaskSpace 只增加生命周期成本却没有图化组织收益，且 projection/event 可能变成单节点长上下文。
- Reproduction:
  - 先审计 `count-call-stack` map；再选择复杂 benchmark sample 跑 standard/R5 各一次。
- Environment:
  - branch `whalecode-alpha`，commit `d699f88`，R5 E4。
- Known facts:
  - `count-call-stack` 是单文件一行修复，单节点本身不构成 map collapse 证据。
  - runtime 已不按 node kind 禁止 edit/test，因此 inspect node 内执行多类动作是边界设计的结果。
  - TaskSpace compact tool schema 与通用 `update_plan` 同时暴露；前者需要逐节点生命周期调用，后者一次调用即可写入完整阶段计划。
  - runtime mechanical init 已创建、绑定并运行一个 blank inspect node，但 compact schema 没有把该 blank task/map 原子替换为 Agent-authored root/node plan 的动作。
- Ruled out:
  - sample 过简单。
  - benchmark map extractor 漏掉实际节点。
- Fix criteria:
  - 至少一个复杂 sample 有任务结构基线、standard/R5 行为、node/edge/event/result 证据；若确认坍缩，根因必须通过 projection/tool contract/runtime state 证据区分，不能直接增加 runtime 拆分策略。
- Current conclusion: map collapse 已确认。Agent 并非没有拆解任务，而是把 6 阶段语义计划写入并行的 `update_plan`；机械 blank node 作为可立即执行所有普通工具的归因槽吸收了完整工作。compact `taskspace_control` 既没有原子初始化 blank root 的能力，也没有与 `update_plan` 相当的批量 map ergonomics，因此“map 必须使用”只在工具归因层成立，在任务语义管理层被旁路。
- Repair conclusion: 已实现并实跑验证 TaskSpace provider 隐藏 `update_plan`、runtime 零节点机械初始化和 Agent-authored `initialize_map`。复杂样本中 Agent 的 5 节点计划已进入 map，证明原始旁路根因已解除；但 `finish_node` 文档称“完成当前节点”而 handler 强制要求 `node_id`，导致 Agent 的收尾动作被协议层拒绝，随后 final hard gate 被重复放大到 227 requests。G2 退出门禁因此只部分通过，P-001 尚不能标记 fixed。
- Authorized repair boundary:
  - 用户确认 TaskSpace 下屏蔽原生线性 `update_plan`。
  - TaskSpace 增加 Agent-authored `initialize_map` 原子动作替代线性计划初始化。
  - runtime mechanical init 只创建空 task/map 外壳；空 map 是允许硬拒绝普通工具和 final 的机制错误。
  - runtime 不从自然语言或旧 plan 推断 map，不做兼容桥接。
- Related hypotheses:
  - H-001
  - H-002
  - H-003
  - H-004
  - H-005
- Resolution basis:
  - complex live sample、raw runtime event、Agent `update_plan` calls、mechanical init 实现和 compact tool schema 形成完整证据链。
- Close reason:
  - not closed
