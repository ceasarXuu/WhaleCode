# v0.0.4 E3 外部审计 R2 资料清单

本清单用于生成 `v0.0.4-E3-外部审计资料包.zip`。R2 是 R1 的审计修订版：保留 R1 的核心证据范围，同时把审计入口、证据分层、不可打包内容和复核口径写得更明确，方便外部审计者快速判断本次 v0.0.4 E3 是否工程 clean，以及 TaskSpace 收益是否成立。

## 0. R2 相对 R1 的变化

| 项目 | R2 处理 |
|---|---|
| 清单入口 | zip 内 `00-清单/外部审计R2资料清单.md` 作为主入口，同时保留 R1 清单用于追溯。 |
| 审计重点 | 明确拆成执行有效性、结果对比、成本对比、TaskSpace 行为模式、guardrails 证据五条线。 |
| 资料范围 | 仍只打包公开可审计材料，不打包 reviewer-only/private oracle、hidden oracle 源、materialized `/app` 工作区和大型缓存。 |
| 结论边界 | 明确 public validator 结果不是人工审计后的最终 benchmark claim；本次仍处于 `audit_required`。 |

## 6. 刻意不打包的内容

以下内容不进入 R2 外部审计包：

- `reviewer-only/private-oracle` 和 hidden/private oracle 源文件。
- hidden oracle stdout/stderr。
- materialized scenario 的完整 `/app` 工作区、Docker build cache、uv cache tarball。
- 大型或可再生成的 validator runtime 临时目录。
- 本地 `docs/testing/v0.0.4/testing/` 暂存目录本身；该目录只用于组包，已加入 `.gitignore`。

## 7. 关键判断口径

- 只有 agent 执行超时可以作为允许的意外 outcome；Docker、validator、path、disk、materialization、report/audit 等异常都应使执行无效。
- 本次 clean run 的 public validator 原始结果是 Standard 7/15、TaskSpace 8/15。
- 本次仍处于 `audit_required`，所以 solved/wrong 是 public validator 原始结果，不是人工审计后的最终 benchmark claim。
- v0.0.4 大体完成了“可审计、可诊断、可区分工程污染”的工程目标，但没有证明“以可接受成本稳定提升 agent 能力”的产品目标。
- 成本结论必须同时看 agent 耗时、validation 耗时、direct tokens、uncached input 和 graph health，不能只看 solved pair 总数。
