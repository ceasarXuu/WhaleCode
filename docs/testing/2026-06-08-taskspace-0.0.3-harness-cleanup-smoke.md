# TaskSpace 0.0.3 Harness Cleanup Smoke

## 目标

验证 0.0.3 的 E3 harness cleanup 修复是否能在真实 Terminal-Bench Docker validator 路径下收敛，重点不是证明 TaskSpace 效用，而是证明 validator timeout 后不会遗留容器阻塞 driver。

## 执行范围

- TaskSpace version: `0.0.3`
- Benchmark: Terminal-Bench
- Sample: `hello-world`
- Source revision: `1a6ffa9674b571da0ed040c470cb40c4d85f9b9b`
- Repeats: `1`
- Agent path: real `whale`
- Validator path: real generated Terminal-Bench Docker validator
- Docker backend: WSL distro `whale-docker`

### Successful Cleanup Smoke

- Run root: `D:\whalecode-alpha\target\bench003smoke-20260608-043849`
- Run dir: `D:\whalecode-alpha\target\bench003smoke-20260608-043849\runs\terminal_bench__hello-world\20260608-043852-857`

Result:

- Driver completed; no manual container stop was required.
- Docker residual query after run returned no `whale.taskspace.terminal_bench=true` containers.
- Both sides timed out public validation at `180s`, so the pair is diagnostic only.
- Pair reported `E1`, `included_in_e3_aggregate=False`, `included_in_utility_aggregate=False`.

Cleanup proof:

| Side | Container | Cleanup | Identity | Container rm | Image rm |
|---|---|---|---|---:|---:|
| left / standard | `whale-tbench-d35bfe8a8e27a1de-18dc51b2` | `ok` | `true` | 0 | 0 |

Interpretation:

- 0.0.3 fixed the original blocker shape: timeout can still happen, but timeout no longer leaves the validator container running and blocking the parent driver.
- The 180s validation timeout is too low for this Docker path on the current machine. Future E3 runs should use the default or higher `ValidationTimeoutSeconds=420` unless the goal is specifically to exercise timeout cleanup.
- This smoke does not prove TaskSpace utility and should not be included in aggregate utility claims.

### Marker Regression Smoke

After the first successful cleanup smoke, one evidence issue remained: timeout stderr wrote `validation_cleanup_result_path` immediately after the timeout message, so metrics/proof extraction did not reliably see the cleanup artifact path. The marker writer was changed to emit a standalone line, and a shorter timeout smoke was executed.

- Run root: `D:\whalecode-alpha\target\bench003smoke2-20260608-044924`
- Run dir: `D:\whalecode-alpha\target\bench003smoke2-20260608-044924\runs\terminal_bench__hello-world\20260608-044928-289`
- Validation timeout: `60s`

Result:

- Driver completed; no manual container stop was required.
- Docker residual query after run returned no `whale.taskspace.terminal_bench=true` containers.
- `metrics.json` now records `validation_cleanup_result_path` for both sides.
- `external-runtime-proof.json` now records cleanup result path, `validation_cleanup_classification=ok`, and `validation_cleanup_identity_matched=true` for both sides.
