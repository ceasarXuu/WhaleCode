### 3.1 资格工具经验

候选测试二进制会把 `CARGO_MANIFEST_DIR` 编译进资源定位逻辑。不同临时候选树复用同一个外部 `CARGO_TARGET_DIR` 会让二进制继续引用已销毁的旧临时路径，产生虚假的 fixture-not-found。最终实现将 Cargo target 放回当前候选临时树，确保源码、编译产物与 fixtures 同生命周期。

Nextest 还必须显式设置 `RUST_MIN_STACK=8388608` 和 `INSTA_UPDATE=no`。未设置大栈时，0.146 的 multi-agent 相关测试会在断言前 stack overflow，这同样不能归类为候选产品失败。

## 7. Go / No-Go 门槛

当前结论为 no-go。只有同时满足以下条件，才能重新评估 vendor cutover：

1. 精确 0.146 tree 能通过 locked workspace 解析，或用户明确选择包含官方修复的新目标版本；
2. qualification runner 隔离 ambient proxy，并证明 core 失败不再出现；
3. app-server 采用能构建 `codex-code-mode-host` 的官方 workspace/just 测试入口；
4. 官方目标 tree 的 TUI version snapshot 与实际版本一致；
5. 五项资格命令重新生成 manifest 且全部通过；
6. replay ledger 随目标 tree 整体重算，禁止混用 0.146 工件与其他版本源码。

上述工作应作为“候选资格修复”小批次先完成。未通过前，不建议启动第四批 brand/home 实际 cutover。
