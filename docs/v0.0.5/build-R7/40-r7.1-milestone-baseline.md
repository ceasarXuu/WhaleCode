## 2. R7 产品目标与当前结论

R7 的产品目标不是重新设计 R6 Rooted DAG，而是在同一份独立持久化 canonical Map、同一套 Runtime、Tool、反馈和恢复基建
上，提供三种 projection 进入 provider context 的策略：

| 策略 | 当前产品合同 | 已知特征 |
|---|---|---|
| `map-always` | 每个请求携带最新全量 projection，并替换上一版 | 动态 replacement 破坏长缓存前缀，低缓存是已知成本 |
| `map-append` | 每个有效请求追加一份最新 projection，旧版本明确标记过时 | 适配线性缓存，但旧 projection 会累计 input |
| `map-request` | Map 作为不可绕过的外部工作状态，由 Agent 主动读取 | 缓存接近 Standard，但 Map 对日常推理的显著性可能较弱 |

三种策略只能在 L5 projection emission 上不同。它们不得拥有独立 Map、状态机、Tool、反馈、恢复路径或专用
语义规则。

当前结论：

- 三种策略及其共享基建已经实现；
- 五层架构 L1-L5 已进入生产路径；
- 当前阻塞包括 L4 非终态连续动作、固定 Tool 成本晋升和 `map-request` 响应级操作漂移；
- 初始化 schema 成本已经明确下降，但候选尚未通过整体晋升门；
- R7 不能宣告完成，也不能依据局部成本收益晋升当前候选。

## 4. 已实现并验证的工程能力

### 4.1 共享架构

- `map-always`、`map-append`、`map-request` 必须共享同一个独立持久化 canonical Map 和 Rooted DAG Runtime；
- Root 是唯一起点并保持 Open，直到 Agent 显式提交唯一 Finish；
- 除 Root 外所有节点至少有一个入边，允许多父依赖，所有节点从 Root 可达并能到达 Finish；
- projection policy 不改变 Tool schema、状态机、反馈、恢复、fork 或 compaction 语义；
- R6 epoch 专属兼容分支不作为 R7 运行前提。

### 4.2 五层内容架构

- L1 使用 Codex 成熟工程框架，并加入 TaskSpace 的价值、Map 模型和 Agent/Runtime 宏观边界；
- L2 以版本化 Core Protocol 说明日常 Map 工作循环和最低恢复方法；
- L3 通过 bundled `taskspace-advanced` Skill 按需暴露复杂 DAG 和长任务经验；
- L4 使用静态、可判别、provider 可见的 Tool schema 表达机械调用合同；
- L5 维护 canonical state、硬规则、原子事务、事实结果和三种 projection；
- Standard 与 TaskSpace 各使用一份完整 Base，TaskSpace 内容不装饰 Standard 普通 Tool；
- DeepSeek 不支持 developer role 时，L2 进入第二条 system message，但仍保留独立 artifact 和版本身份。

### 4.3 Tool、反馈与连续动作

- 初始化 Map 与首个真实普通 Tool 已合并为一个 provider response；
- 初始化继续由 Agent 提交 Root、Work、Finish、ID、目标和 edges，Runtime 不代建任务图；
- Root、Initial Work、Additional Work、Finish 在初始化 wire 中保持角色分区；
- 普通 Tool 的原生业务参数保持顶层结构；
- `apply_patch` 保持原始文本，不进入通用 nested dispatcher；
- 单 response 最多执行一个 Patch，但允许 lifecycle boundary 与该 Patch 合法配对；
- preflight 失败时零业务执行、零 Map commit；
- 业务 Tool 失败和 Map 状态失败分别返回，不互相伪装；
- 同一失败只进入上下文一次，反馈不注入下一步建议；
- provider schema、carrier、preflight、dispatch、commit 和最终状态均有结构化日志。

### 4.4 工程环境与评测

- Docker benchmark 已统一使用真实 bundled Skills，不再通过禁用本机或内置 Skills 制造控制变量；
- Standard 与三种 TaskSpace 策略使用相同 model、image、binary、样本和 capability set；
- simple 与 complex 样本都具有 public、hidden 和 external validation；
- request、input/output tokens、cache、wall time、Tool schema、动作路径和 Map 形状能够统一观察；
- FLA-8 直接门禁从原始 `summary.csv`、`aggregate.csv` 和 `trace-analysis.json` 反算结论；
- FLA-9 因一条 incomplete observation 不生成正式 aggregate，直接门禁改为逐条核对 24 个 raw observation，
  不把重建成本冒充正式统计；
- 构建缓存保留，异常膨胀的 Rust incremental 数据已有清理和预防记录。

## 6. 五层整体约束

| ID | 约束 | 后续变更必须满足 |
|---|---|---|
| C-01 | 单一语义所有权 | 同一规则只有一个权威层，其他层只引用身份 |
| C-02 | Agent 负责语义 | Runtime 只验证状态机底线，不代拆任务、选节点或判断工作质量 |
| C-03 | 语义忠实透传 | 先排查 payload、反馈和 projection 的丢失、扭曲、残缺或重复 |
| C-04 | 内容按必要性分层 | 宏观框架在 L1，日常协议在 L2，高级经验在 L3，机械合同在 L4，动态事实在 L5 |
| C-05 | Tool 领域语义准确 | Tool 说明能力、参数、结果和副作用，不教授完整工作方法 |
| C-06 | immutable capability epoch | 同一 epoch 内 Base、L2 和 Tool schema 字节固定 |
| C-07 | projection 只在 L5 不同 | 三种策略不得建立平行 Runtime、Tool 或反馈分支 |
| C-08 | Map 是 canonical rooted DAG | 唯一 Root、唯一 Finish、全图可达，Agent 设计图，Runtime 守硬不变量 |
| C-09 | 连续动作不可回退 | 初始化和非终态 boundary 必须与后继真实 Tool 同 response |
| C-10 | Patch 保真与单 Patch | 保留原生顶层文本，单 response 最多一个 Patch |
| C-11 | Standard 隔离 | TaskSpace schema、硬门和反馈不得进入 Standard |
| C-12 | 原子事实型失败 | preflight 失败零执行零提交，失败不改写、不建议、不重复包装 |
| C-13 | 成本是发布约束 | 必须观测完整 tools、messages、input、cache、request 和累计成本 |
| C-14 | 评估必须可归因 | 每次只改一个策略，比较臂使用相同 commit、binary、image、model 和样本 |
| C-15 | 无兼容债务 | 不保留旧 wire、双 parser、静默 fallback 或行为兼容分支 |
| C-16 | 机械角色由结构表达 | 不把 Root、Work、Finish 等角色压平后依赖自然语言维持互斥 |
| C-17 | Map 独立持久化 | Map Store 是唯一事实源；Session/Runtime 只持引用或可丢弃缓存，rollout 不负责恢复 Map |

这些约束不可使用“局部收益更大”互相抵消。任意一条回退都使候选整体失败。

## 8. R7.1 当前阻塞

### 8.1 R-10：非终态连续动作仍是事后惩罚

当前 `taskspace_control` 和普通 Tool 是两个独立 provider schema。前者无法要求后者作为同一 response 的 sibling，
后者也无法从自身 schema 要求前置 control。sequence preflight 只能在 Agent 已经生成单独 boundary 后拒绝。

表现：

- 旧基线三种 TaskSpace arm 共 25 次 protocol failure；
- 当前候选共 28 次同类 failure；
- 一次 `map-append` run 已完成业务验证，但 Map 未闭合并最终 interrupted；
- 该问题跨版本、跨 projection policy，不能归因于某个 projection 或初始化角色修复。

因此，“Runtime 能拒绝非法 response”不等于“连续动作合同已经实现”。

### 8.2 R-19：固定成本候选尚未整体晋升

角色分区 wire 已把 Tool section 降到 46,926 bytes/request，但 R-19 的验收同时要求：

- 不回退连续动作；
- 不产生独立初始化；
- 不破坏 Patch；
- 不侵入 Standard；
- simple、complex 和 held-out 行为不退化；
- 三种 projection 使用同一 capability epoch。

R-10 和 R-22 未关闭、held-out 尚未执行前，R-19 保持 open。

### 8.3 R-21：TaskSpace 子代理 handoff 已关闭

COE `2026-07-18-03-15-r7-subagent-map-restore.md` 记录的基线失败为：

```text
cargo test -p codex-core action_map_completion_watcher_advances_next_spawn_to_next_node
map_checkpoint_delta_chain: domain_invariant:
TaskSpace current binding and main lease are inconsistent.
```

修复后 parent、fork 和 child 通过 binding 读取同一 Store Map；nested spawn 的硬门先执行 Store-backed read；
child attach 失败会关闭 spawn edge、发送 Shutdown、移除 thread 并释放 registry slot。原失败测试
`action_map_completion_watcher_advances_next_spawn_to_next_node`、nested spawn、completion watcher 和
abort-after-spawn-failure 定向门均通过，不再依赖 rollout 恢复或复制 Map。

### 8.4 R-22：multi-Patch 和事后 Map 补账仍是开放行为问题

FLA-8 的 `map-request` 复杂样本 3/3 生成多个分别合法的 sibling `apply_patch`，由 response-wide preflight
零执行拒绝；其中一次长尾运行在业务工作完成后才通过多个机械动作补做 Map 生命周期。R-12 已关闭的是 Patch
正文保真和“绝不部分执行多个 Patch”的安全底线，并不代表重复 multi-Patch attempts 和事后补账已经解决。

当前没有证据证明 projection policy 是因果根因。修复前必须先做只改变 projection 可见性或 Tool 合同的单变量
实验，不得让 Runtime 推断 Patch 意图或代替 Agent 推进 Map。

### 8.5 R-23：canonical Map 的持久化所有权已关闭

基线曾由 `SessionState` 直接持有完整 Map，并把 snapshot/delta 写入 rollout。A0 候选已改为独立
SQLite Map Store 唯一持有 canonical snapshot；Session 只保存 Store handle 与可丢弃 Runtime cache，
resume/fork/child 按 binding 读取同一 Map，rollout snapshot/delta 恢复和旧 CLI replay 已删除。

目标模型已经明确：

- Map Store 独立持久化唯一 canonical Map；
- Runtime 只负责操作、硬规则验证和可丢弃缓存；
- Session、主 Agent 和 child agent 只持有 Map/node/lease/revision 引用；
- rollout 只记录对话、Tool 事实、审计事件和 revision 引用；
- resume、fork 和 child 访问同一 Map，不重放重建；
- 不保留旧 checkpoint/delta 恢复 fallback，不维护双事实源。

Store 的事务、并发、幂等、hash 损坏、重启、终态 round-trip 和无 Store 禁止 rollout 恢复门已通过。
CLI、PowerShell observer、App Server、TUI 和 interactive show 均通过 Store-backed read 获取当前 snapshot；
Rust、PowerShell、Python 与 Shell 残留门禁止旧 replay 入口复活，并已进入默认 action-map 回归。七轮空白
对抗性审查发现的 child binding、观测脚本、cache read 和 snapshot parser 缺口均已修复，R-23 关闭。

### 8.6 尚未进行正式统计决策

每臂每样本 3 次只用于接线、路径和回归诊断，不能证明策略收益或非劣。repeat-10 和 held-out 对抗样本必须在
R-10、R-22 修复并通过定向门后执行，否则会把已知协议失败混入产品策略比较。

## 10. 变更停止条件

后续任何候选出现以下情况必须立即停止，不得继续叠加修复：

1. 为解决成本而改变 Agent/Runtime 语义边界；
2. 为解决 Agent 错误而先增加 Runtime 语义判断；
3. 为解决连续动作而恢复完整 lifecycle 联合到所有普通 Tool；
4. 为缩短 schema 而擦除机械角色；
5. 为兼容旧 wire 增加双 parser、fallback 或静默默认值；
6. TaskSpace 装饰进入 Standard；
7. Patch 被嵌套、转义或通过通用 dispatcher 执行；
8. 某个 projection policy 获得专用 Tool、状态机或反馈路径；
9. 成本改善伴随成功率、闭合率或反馈完整性回退；
10. 同一实验同时改变多个策略而无法归因。
11. 为修复 child/resume/fork 而重新引入 rollout Map replay、Session-local authoritative Map 或双事实源。

触发停止条件后，应先更新 COE 假设和证据，再修改整体约束或提出新候选，不得用局部补丁继续推进。
