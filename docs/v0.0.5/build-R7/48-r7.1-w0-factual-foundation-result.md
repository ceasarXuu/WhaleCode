## 1. 阶段结论

前三轮对抗性审查累计接受的 blocking finding 已完成工程修复。Round 2 指出的
candidate/canonical 状态域、provider attempt 全集、ToolSearch/普通 Tool carrier、重复输出与 provenance
问题均有正反回归。随后两次正式矩阵又暴露并收敛了两个观测链缺口：

1. Agent 未完成或被中断的真实观察不得被 harness 删除；只要原始证据完整，就继续封存并以
   `comparison_eligible` 区分，符合 C-14；
2. provider response 的 supplemental 出现在 `token_count` 之后时，不能按遍历位置绑定到下一请求；
   observer 现由 `affected_call_ids` 反查唯一 owning request，并要求 call 集合精确相等。

Round 3 又发现三个实现完整性缺口：真实 `ToolSearchFailureV3` producer 与 observer 的 provenance
合同漂移、缺少 state rejection + ToolSearch 的精确组合回归、TaskSpace MCP fixture 不是完整生产形态。
修复候选统一了生产 ToolSearch provenance，补上真实状态机 complete/reserve 冲突与 ToolSearch sibling
回归，并让 Standard/TaskSpace 与 metrics fixture 都使用 namespaced Function MCP 形态。

Round 4 replacement reviewer 又找出四个阻断缺口：supplemental failure 对畸形/未知/残缺结构仍可能
fail-open；state rejection + ToolSearch 测试未穿过异步生产入口；ToolSearch provenance 仍从错误文本推断
来源；结果文档的状态拒绝数量和后续 `read_map` 数量已经与工件不一致。当前提交已完成对应修复：

1. supplemental failure 的结构、布尔失败语义、角色、scope、affected call 集合和 ToolSearch cause
   全部 fail-closed；
2. 组合回归穿过 `execute_response_tool_sequence`，并以 poisoned dispatch 证明拒绝发生在零执行之前；
3. provider-response rejection 与 ToolSearch execution failure 使用不同的 typed 生产分支，不再解析
   `error.message` 决定来源；
4. 矩阵自动输出被拒请求数、违规事实数、canonical/candidate 状态对和下一请求动作，文档不再人工统计。

Round 5 replacement reviewer 复现了两个更窄的 observer blocker：

1. malformed supplemental 只有在 `schema_version` 位于首字段时才 fail-closed，且单元素
   `affected_call_ids` 字符串会被 PowerShell 隐式提升为数组；
2. 状态汇总按 `node_id + canonical state + candidate state` 内容启发式去重，会合并同一节点但
   subjects、allowed states 或前驱集合不同的独立 violation。

当前提交删除了这两类启发式：保留 schema family 的识别与字段顺序无关，supplemental 使用严格 JSON
类型和值合同；状态汇总只按 producer 已提供的 `copy_group_id + affected_call_ids` 合并 sibling copies，
并按原始 ordinal 保留完整 violation。

Round 6 replacement reviewer 随后发现四个证据身份 blocker：保留 family 仍可由 root/schema array 或
unicode escaped malformed payload 绕过；provider/skip/bound provenance 未绑定精确 producer identity；
request path 丢弃 output/reasoning/total token；resolved manifest 只封存哈希而未验证四臂内容身份。当前
提交 `2005442d3` 已逐项修复。

Round 7 replacement reviewer 继续找到四个更深的证据权威 blocker：

1. supplemental 保留 JSON family 对递归重复属性等形态仍可 fail-open；
2. failure 与真实 output、owning request、skip cause、bound reservation 的因果顺序仍可伪造或被后续
   ordinary output 覆盖；
3. token identity 可接受字符串、fraction 或 double，超过 IEEE-754 精确范围后仍可能表面对账；
4. resolved manifest 仍可与同一次运行生成的 matrix manifest 相互自证，没有独立冻结 sample/model/image/
   sandbox/provider wire/Tool identity 的评估权威。

当前候选增加了严格 JSON/provenance/Int64 门，并引入独立 evaluation contract 与 production authority hash
chain。第一次正式矩阵在报告阶段暴露 `performance-observation.ps1` 将整数 token 转成 double，已判为无效并
弃用；修复后第二次 24-run 矩阵通过严格 report/provenance/final-status gate。GI-005、GI-007 仍只处于
`validating`；必须由 Turing 之外的无上下文 reviewer 执行 fresh replacement review，通过前不得关闭，也不得
进入 W1。

Round 8/9 又先后证伪了未绑定 Tool output、错误 token/count 类型、脏候选字节、残缺 state violation、
affected call 顺序集合化和权威文档漂移。对应反例均已转为 fail-closed 回归。Round 9 修复后的首次正式汇总
继续发现一个更窄的实际形状缺口：普通 Tool 返回的 `metadata.shell_exit_code` 没有进入退出码分类，完整的
`apply_patch` 失败因此被误判为无效证据。`ab2595847` 只读取该显式机械字段，不解释错误文本或 Patch 语义；
随后 current-candidate 矩阵完整通过。

## 4. 状态反馈复验

旧 blocker 的关键反例是：同事务将 Work 临时完成后又向它声明动作，失败反馈只给
`actual_state=completed`，Agent 将其误认为 canonical 已提交。当前合同改为：

- `canonical_state_before_transaction`
- `evaluated_state_at_violation`
- `allowed_states_at_violation`
- canonical/evaluated 两套未满足前驱

聚焦测试稳定得到 canonical `ready`、evaluated `completed`、`state_commit=false`。本次正式矩阵自动汇总出
16 个 `node_state_invalid` request 和 16 份违规事实：

| arm | 请求 | 状态对（违规数） | 下一请求 `read_map` |
|---|---:|---|---:|
| map-always | 5 | `ready->completed:3, waiting->waiting:2` | 0 |
| map-append | 5 | `absent->waiting:1, waiting->waiting:4` | 0 |

这里的箭头只表示 `canonical_before_transaction -> rejected_candidate_at_violation`，不是状态迁移。矩阵自然
触发了 Waiting 和 Ready 拒绝；两套状态不同的反例继续由异步生产入口确定性测试覆盖。
16 个请求中 2 个下一请求
