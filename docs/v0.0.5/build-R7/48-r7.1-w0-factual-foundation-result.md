## 4. 状态反馈路径

| Request | Agent 动作 | Runtime 返回的机械事实 | 后续表现 |
|---:|---|---|---|
| 12 | 尝试在 `fix` 执行 Patch | `fix` 为 `waiting`；允许 `ready/in_flight`；未满足前驱为 `explore` | 未重复相同请求 |
| 13 | 同事务完成 `explore` 并继续在 `explore` 执行动作 | rejected candidate 中 `explore=completed`，但 canonical revision 17 仍为 `ready`；返回字段未区分状态域 | Agent 误认为 canonical 已 completed |
| 14 | `read_map` | revision 17 的 `explore=ready`、`fix=waiting` | Agent 才纠正对上一条反馈的理解 |
| 15 | 完成 `explore` 并在 `fix` 执行 Patch | control state commit 成功 | 进入普通 Patch 执行路径，Patch 自身失败 |

这条路径反而证明反馈虽然保留了底层候选状态，但没有声明状态所属范围，Agent 会把拒绝事务中的
evaluated state 误认为 canonical state。修复只能补全机械状态域，不得通过 Runtime 建议、自动改绑或替
Agent 选择节点来掩盖问题。
