旧 blocker 的关键反例是：同事务将 `explore` 临时完成后又向它声明动作，失败反馈只给
`actual_state=completed`，Agent 将其误认为 canonical 已提交。本轮合同改为：

- `canonical_state_before_transaction`
- `evaluated_state_at_violation`
- `allowed_states_at_violation`
- canonical/evaluated 两套未满足前驱

聚焦测试稳定得到 canonical `ready`、evaluated `completed`、`state_commit=false`。正式矩阵未再出现
“根据 candidate completed 直接判断 canonical completed”的 trace。

`map-request` 的简单样本中有 2 次 Waiting 拒绝后显式 `read_map`。两次拒绝均已直接携带
canonical=`waiting`、evaluated=`waiting`、未满足前驱和 canonical revision，随后 Agent 正确完成前驱并继续。
这属于外部 Map 模式下的保守读取，未发现反馈字段丢失或状态域误读；是否要降低这类读取属于后续行为/成本问题，
不能通过 Runtime 建议或自动纠正解决。
