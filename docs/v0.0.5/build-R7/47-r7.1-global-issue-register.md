## 1. 权威与原子边界

R7.1 只使用 `R71-<两位顺序号>` 一组当前编号。每个编号就是一个可独立关闭的 Phase，不再设置小数子任务。

本文件中的职责分为两部分，但只有一个物理事实源：

1. 第 2 节嵌入的 JSON 是 Phase 身份、状态、依赖、根因、关闭结果、晋升门和证据事件的机器权威；
2. 第 3～5 节是同一合同的读者投影和工程说明，不得维护平行状态；
3. `test-r7-unified-execution-plan.ps1` 必须同时验证 JSON Schema、依赖 DAG、条件关闭、根因覆盖、晋升可达性
   和读者投影一致性；
4. 新增 Phase 必须插入成本门之前，重排后续当前编号，并让所有成本阻断项成为动态成本 Phase 的祖先；
5. 路线决策、生产实现、行为诊断、成本验收和产品晋升分别编号；
6. 诊断发现一个或多个根因时，诊断 Phase 可用 `root_causes_identified` 独立关闭，但必须同时登记
   `root_cause_id -> phase_id` 映射；派生 Phase 必须反向声明父诊断，且自动进入成本与晋升祖先链；
7. 允许无写冲突的多个 Phase 并行实施；所有 `in_progress` Phase 的 `change_domain_key` 必须互不相同，
   并使用独立 worktree、提交和证据；
8. `FLA-*`、`A2-*`、`W*`、`R71-GI-*` 和上一版编号只允许出现在历史证据和第 6 节迁移投影中。

状态与关闭结果是两类不同事实：

- 状态：`repair`、`planned`、`decision_pending`、`verification_pending`、`gated`、`in_progress`、`closed`；
- 未关闭 Phase 的 `closure_outcome` 必须为 `pending`；
- 已关闭 Phase 必须提供其 `allowed_closure_outcomes` 中的结果，以及可校验路径、SHA-256、artifact type
  和 schema 的 `evidence_artifact`；
- Phase evidence 只接受 `r7-phase-evidence-v1.schema.json`，且每条 record 必须包含该 Phase
  `observability.required_fields`；held-out 只接受独立 sealed-set schema；
- `root_causes_identified` 必须同时提供非空 `spawned_repairs`，派生 Phase 不能是自身、祖先或已关闭节点；
- `gated` 不是待决策；`in_progress`、`decision_pending` 和 `current_phase_id` 都必须依赖已关闭节点；
- 成本、冻结、正式评测和晋升角色由 Phase 类型与严格末端依赖链决定，不接受可手工清空的 blocker 标志。
- nested boundary、multi-Patch Runtime safety 和 Agent behavior 使用稳定 route role；失败只能
  `spawn_atomic_phase`，所有既有 Phase 的复用统一为 `forbidden`。

实现依据：

- [PowerShell Test-Json](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/test-json)
  的 `-SchemaFile` 用于 JSON Schema 验证；
- [JSON Schema 条件校验](https://json-schema.org/understanding-json-schema/reference/conditionals) 的
  `if/then/else` 用于关闭状态的条件字段约束；
- [JSON Schema array](https://json-schema.org/understanding-json-schema/reference/array) 的
  `uniqueItems` 用于 ID、依赖和证据字段去重；
- [PowerShell Get-FileHash](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash)
  的 SHA-256 用于验证关闭证据与 sealed sample manifest 的内容身份；
- [JSON Schema object](https://json-schema.org/understanding-json-schema/reference/object) 的
  `additionalProperties: false` 用于拒绝重新引入可篡改 blocker 等未声明字段；
- 自有 validator 只负责 JSON Schema 不表达的图可达性、根因覆盖和读者投影一致性。

## 5. 依赖、并行与停止规则

```text

  R71-01  R71-02  R71-03  R71-04  R71-05  R71-06  R71-07
```

5. engineering held-out 与 promotion held-out identity 必须不同且不可互换；
