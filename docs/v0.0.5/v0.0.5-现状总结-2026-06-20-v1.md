## 1. 一句话结论

v0.0.5 不能收口。

它已经完成了一批成本治理和证据治理基础设施，包括 `state_commit`、`OutputReferenceV1`、`ContextProjectionV1`、provider request budget 观测、release/start gate、实验等级制度、active provider-visible composition 等；但当前 Terminal-Bench P0 诊断结果显示：

- TaskSpace 正确率没有守住。
- token 和时间成本仍远高于 2x 目标。
- 新增 compact history 过滤还引入了 ChatCompletions tool-call 协议破坏 bug。
- 正式 `terminal-bench_E3-P0_3_5` 尚未运行，也不应在当前代码状态下运行。

因此，当前 v0.0.5 的准确状态是：

```text
工程基础设施大量完成，但 active cost-control / correctness-preserving execution path 尚未完成。
版本状态：NOT READY TO CLOSE。
下一步：先修 provider-visible tool-call/output 成对不变量，再继续做非 agent gates 和低成本 targeted diagnostic。
```

## 2. 目标回顾

v0.0.5 的核心定位是：

```text
TaskSpace v0.0.5 = Protocol Compaction + Context Replay Control + Map Self-Management Foundation
```

原始目标可以拆成两组：

| 目标 | 目标值 | 当前状态 |
|---|---:|---|
| TaskSpace agent walltime | <= Standard 2x | 未达成，Terminal-Bench P0 诊断约 3.63x-3.66x |
| TaskSpace direct input+output tokens | <= Standard 2x | 未达成，Terminal-Bench P0 诊断约 11.39x-16.29x |
| model request count ratio | <= 2.5x | 未达成，诊断中 TaskSpace 内部请求可达 128.40x 或 435 次/3 pair |
| avg input/request ratio | <= 1.25x | 未达成，TaskSpace 每次请求仍常见 35K-61K input token |
| TaskSpace solved | >= Standard solved - 1 | 内部矩阵满足；Terminal-Bench P0 诊断不满足 |
| large raw output replay | 0 | 已有 output reference 机制，但 active path 仍需证明 |
| map active context 不线性膨胀 | 需要证明 | map 结构未爆炸，但 provider-visible context 仍偏大 |
| 正式 E3 口径 | `terminal-bench_E3-P0_3_5` | 尚未运行，当前禁止运行 |

关键修正：v0.0.5 的目标不是“只做可观测”。目标文档明确要求实际成本控制，2x 成本目标是版本成功条件之一。当前只能说可观测和门禁基础设施已有明显进展，不能说成本控制目标已经达成。

## 3. 证据口径修正

本轮工作中发现过一次严重口径风险：内部矩阵接近 100% 的结果曾经容易被误读为 Terminal-Bench E3 正确率。

已修正规则如下：

| 口径 | 当前定义 |
|---|---|
| E1 | 内部机制冒烟，只证明某条机制能跑通 |
| E2 | 内部工程回归，只证明内部 fixture 效用和回归 |
| E3-candidate | 外部候选证据，仍缺 E3 门禁 |
| E3 | 外部效用证据，必须 repeats >= 5、源版本固定、验证器保真、产物成对、审计闭环 |
| E4/E5 | 当前仅为治理定义，尚不能使用 |

正式命名规范已经改为：

```text
数据集名称_子集名称_sample数量_repeats次数
```

例如：

```text
terminal-bench_E3-P0_3_5
```

当前必须严格区分：

| 名称 | 性质 | 能否用于 release pass |
|---|---|---|
| `taskspace-internal_E2-v005-regression_3_5` + E1 smoke | 内部工程矩阵 | 不能 |
| `terminal-bench_E3-P0_3_1` | 低成本诊断 | 不能 |
| `terminal-bench_E3-P0_3_2` | 低成本诊断 | 不能 |
| `terminal-bench_E3-P0_3_5` | 正式 P0 release proof 目标 | 可以，前提是全部 gate 通过 |
| `terminal-bench_E3-v004-clean_3_5` | v0.0.4 clean 同口径回归对比 | 不能替代 P0 proof |

已废止或降级的结论：

- `24/25` 只能描述为内部 E1/E2 混合工程矩阵结果，不能描述为 Terminal-Bench E3 正确率。
- `15-closeout-summary.md` 是历史阶段性记录，已被 2026-06-19 P0 诊断和后续 COE supersede。
- 当前不能声明“正确率未下降已经坐实”。
- 当前不能声明“v0.0.5 可以关闭，成本优化放到下一版本”。

### 5.6 2026-06-20：provider-visible tool-call history 根因确认

用户要求 TaskSpace-only 跑 `terminal-bench_E3-P0_3_1` 看修复情况，并要求中途发现问题立刻停。

执行：

- 只跑 `processing-pipeline` TaskSpace-only。
- 使用当前 debug build。
- 没有继续跑完整 E3。

结果：

- `run-001` 因 PowerShell native stderr wrapper 产生外层问题，不作为核心根因。
- `run-002` 进入真实 agent 流程后失败。
- 失败时间约 29.859s。
- 无 last message、无 edits、无 validation。
- provider error：

```text
An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'.
(insufficient tool messages following tool_calls message)
```

COE 结论：

```text
H-003 confirmed:
v0.0.5 provider-visible compact-history filter 按单条 item 删除历史。
它把一个被 TaskSpace gate 阻断的 shell_command output 识别为 LegacyTaskspaceToolOutput 并删除，
但保留了对应的 shell_command function call。
ChatCompletions adapter 因此发出 assistant tool_calls，却没有紧随其后的 matching tool message。
provider 拒绝请求。
```

关键边界：

| 事件 | 事实 |
|---|---|
| 前序 7 个并行 read | call/output 都存在，不是并行 output 丢失 |
| 触发 call | `shell_command Get-Command bash ...; Get-Command sh ...` |
| TaskSpace gate | 当前 inspect 节点不允许 `unknown` action class |
| blocked output | 包含 `TaskSpace blocked this tool call` 和 `TaskSpaceGateRecoveryV1` |
| active projection | 紧随其后插入 compact projection |
| 过滤器行为 | 删除 output，保留 call |
| 最终错误 | ChatCompletions tool-call pairing invalid |

当前状态：

- 根因已确认。
- 修复方案已提出，但代码尚未实现。
- 这是当前阻止继续 TaskSpace diagnostic 的首要 bug。

## 8. 当前最重要的根因链

### 8.1 请求数和 token 成本根因

v0.0.5 仍然没有解决 v0.0.4 的核心乘法效应：

```text
总成本 = 模型请求次数 * 每次请求上下文大小
```

当前证据：

- `_3_2`：TaskSpace 5 次执行合计 642 个内部请求。
- `_3_1`：TaskSpace 3 次执行合计 435 个 rollout requests。
- 每次请求仍常见 35K-61K input tokens。
- 所以即使 map 结构没有爆炸，总 token 仍可达到 Standard 的 11x-16x。

### 8.2 正确率下降根因

当前不是单一任务域失败，而是 TaskSpace runtime/path 失败：

- `_3_1` 先暴露 broad inspect recovery gate contradiction。
- 修复后 targeted smoke 又暴露 provider-visible history tool-call pairing bug。
- 说明 v0.0.5 的成本治理和 gate hardening 对真实 agent 路径仍存在协议/状态机风险。

### 8.3 最新阻塞根因

当前首要阻塞：

```text
provider-visible history filtering 不是 tool-call/output 成对感知的。
```

这会在 ChatCompletions 模式下制造非法 provider message。修复原则必须是协议不变量优先：

```text
保留 call 就必须保留 matching output。
删除 output 就必须删除 matching call。
大 output 可以压缩为 synthetic tool output，但不能消失。
```
