##### Blocking Findings

- `B5-R1-F1`：旧 reborn/restart 仍是活跃生产入口。
  - Broken assumption: 旧生命周期只剩不可晋升历史证据。
  - Failure scenario: CLI、TUI 或 App Server 调用旧入口后，Core 将已有 canonical Map 清为 `null`。
  - Trigger condition: 对已有 active/closed Map 使用 `--task-reborn`、`/task-reborn` 或
    `thread/actionMap/restart`。
  - Impact: completion、result、terminal history 和唯一事实源可被丢失。
  - Proof needed: 删除完整可达链，并用残留门证明生产入口为零。
- `B5-R1-F2`：空白或重复 `call_id` 的拒绝晚于 Store reservation commit。
  - Broken assumption: 完整 response identity 已在零执行 preflight 中闭合。
  - Failure scenario: 无效 ID 先创建 InFlight reservation，随后在 owner binding 或 HashMap 配对中失败。
  - Trigger condition: initialize、execute 或 reopen response 含空 ID、重复 sibling ID，或 control 与
    sibling 共用 ID。
  - Impact: Map 可遗留无法正常闭合的 reservation，违反零部分提交。
  - Proof needed: precommit response-wide identity 校验、无可失败的 postcommit pairing，以及真实
    StateDB revision/reservation 断言。

##### Non-blocking Risks

- `B5-R1-F3`：Root 被加入 `active_frontier`。
  - Broken assumption: frontier 只表示 Agent 可执行 Work。
  - Failure scenario: Agent 看到不可绑定普通 Tool action 的 Root 位于动作前沿。
  - Trigger condition: active Map 中 Root 派生为 Ready。
  - Impact: projection 对图事实的反馈发生再解释和语义失真。
  - Proof needed: frontier 按 `NodeRole::Work` 过滤，并保留 Root 的全局事实展示。
- `B5-R1-F4`：lifecycle oracle 允许 final Work 处于 Ready 或 InFlight，但 finish 实现要求 reservation
  已清空。
  - Broken assumption: oracle 与生产终态前置条件相同。
  - Failure scenario: 机器合同把生产实现必然拒绝的 InFlight 终态误标为合法。
  - Trigger condition: final Work 仍有 reservation 时调用 `finish_map`。
  - Impact: 合同门可能掩盖实现或 fixture 回归。
  - Proof needed: oracle 明确 final Work Ready 且 reservation 为空。
- `B5-R1-F5`：活跃 benchmark observer 仍按 R6 lease/blank-map marker 解释动作。
  - Broken assumption: benchmark 已只观测现行 reservation/canonical projection。
  - Failure scenario: 当前 run 被旧模型 marker 分类，产生错误的性能或行为结论。
  - Trigger condition: observer 处理 TaskSpace control/Tool trace。
  - Impact: A2-C/D 的比较证据不可信。
  - Proof needed: observer 只读取 Store reservation、Tool output 和 canonical projection。
