### Reviewer Outputs

#### reviewer-output-1

##### Summary
Non-agent validation is useful enough to justify asking for approval to run real E3/live Agent validation, but the release gates were not honest enough to support PASS/PARTIAL release conclusions from non-agent artifacts alone. The main issue was that synthetic top-level JSON could satisfy `write-release-decision.ps1`.

##### Blocking Findings
- B1. Release decision can PASS from synthetic or non-E3 evidence.
  - Broken assumption: `write-release-decision.ps1` cannot produce PASS from incomplete or synthetic evidence.
  - Failure scenario: hand-written top-level gate JSON and one minimal taskspace metrics file can produce PASS.
  - Trigger condition: top-level files contain passing fields but no E3 manifest, sample-origin proof, pair count, live-agent provenance, or benchmark-run identity exists.
  - Impact: user may trust fixture compatibility as release evidence.
  - Proof needed: release decision verifies benchmark provenance, active profile config, included pairs, and artifact generation lineage.
- B2. Output-reference gate can pass with no output-reference evidence.
  - Broken assumption: output-reference artifacts/events cannot be silently absent from release evidence.
  - Failure scenario: `output-ref-events.jsonl` exists but is empty or `{}`, no runtime output refs exist, and gate still passes because replay count defaults to 0.
  - Trigger condition: missing/empty TaskSpace metrics, empty event file, or no large-output path exercised.
  - Impact: gate proves only absence of detected replay, not output-ref creation or slice capability.
  - Proof needed: require valid `taskspace-output-ref-event-v1` creation events and runtime output-ref count, or explicit not-applicable scenario metadata.
- B3. Corrected map-management contract narrows runtime requirements without enough proof.
  - Broken assumption: map-management as snapshot-derived report contract is an acceptable v0.0.5 correction.
  - Failure scenario: runtime never manages active memory; scripts classify items after the run.
  - Trigger condition: real E3 depends on runtime context behavior while release gates inspect only post-run report summaries.
  - Impact: user may think active map self-management is implemented when only report/classification is implemented.
  - Proof needed: reword status as report-only foundation or provide live evidence of projection behavior.

##### Non-blocking Risks
- R1. `state_commit` replay can freeze a bad partial/rejected commit ID.
  - Broken assumption: replay/idempotency cannot hide recovery edge cases.
  - Failure scenario: same `commit_id` reused with corrected payload after partial/rejected outcome replays the old outcome.
  - Trigger condition: model retries corrected payload with the same commit id.
  - Impact: recovery requires a new commit id.
  - Proof needed: test and document retry semantics.
- R2. Projection parser is text-fragile.
  - Broken assumption: artifact parsers cannot misclassify active/shadow.
  - Failure scenario: projection header wording changes and parser reports unknown/unavailable.
  - Trigger condition: runtime prompt text changes from exact headers.
  - Impact: release gate may fail or be spoofed by text fixtures.
  - Proof needed: emit structured projection events directly.

##### User-Perspective Checks
- Usability: risk - user can understand real E3 has not run, but "complete enough" wording needs a stronger "not release validated" warning.
- Ease of use: risk - approval decision is safer if release status is described as unproven until real E3.
- Ease of understanding: risk - map-management must be called report-only foundation, not full runtime active-memory management.

##### Required Fixes
- Add provenance gates to `write-release-decision.ps1`.
- Make output-ref gate require real valid events or explicit not-applicable evidence.
- Rename map-management status to report-only foundation unless runtime active-memory behavior is proven.
- Add release-decision negative fixtures for empty JSONL, missing metrics, missing E3 manifest/provenance, shadow-only projection, and no TaskSpace pair metrics.

##### Missing Tests
- Release decision must fail when `output-ref-events.jsonl` exists but has no valid output-ref events.
- Release decision must fail when there are no taskspace `metrics.json` files.
- Release decision must fail when top-level summaries are present but no E3/provenance manifest exists.
- `state_commit` replay after partial/rejected outcome should be tested and documented.
- Map-management should test that report classifications correspond to active projection behavior, not only summary shape.

##### Missing Logs / Observability
- Release decision lacks provenance fields: `run_type`, `agent_invoked`, `profile`, `sample_origin`, `pair_count`, `included_pair_count`, `generated_by`.
- Output-ref events do not require artifact-file existence validation.
- Map-management summary does not show whether retention classes affected model-visible context during the run.
- Routing decision logs are benchmark-prompt controlled, but release evidence should say whether routing was report-only or active prompt-injected.
